# BE-03: F12/F14 delivery, files and closure

## Changes

- Final delivery uses an internal read-only `QuarantineReleaseGate` backed by
  `ComplianceRepository`, independent of F08 actor authorization. Missing or
  expired clearance yields 409 `QUARANTINE_RELEASE_REQUIRED`.
- Existing `activateNextLeg` writes the valid `CONFIRMED` state; the native
  lifecycle test verifies the next leg can then start through F12.
- Handover timestamps before departure yield 422
  `HANDOVER_TIME_BEFORE_DEPARTURE`. F12 leg completion uses the same code.
- F12 datetime2 writes/reads and F14 handover writes consistently use UTC
  wall-clock values. Tests run with the host JVM timezone (Asia/Saigon) and
  include handover input with a +07:00 offset.
- Existing F14 file endpoints now have explicit security matchers ahead of
  the general customer-only transport-order route. Staff access checks live
  roles and assignments to the current plan; customers can read owned
  handover evidence but cannot read internal actual-cost files.
- A completed F12 driver assignment remains usable for F14 custody handover
  and file access. Cancelled/inactive assignments remain excluded.
- Manager POST `/api/transport-orders/{orderId}/handovers/close-order`
  requires DELIVERED and a matching order rowversion. Parent locking,
  CLOSED mutation, updated timestamp and canonical append-only CLOSED audit
  share a transaction. Audit-based operation replay prevents duplicate close
  events and rejects reuse of the UUID with a changed version.
