# BE-01: payment preparation, catalogue reads and plan pricing

## Payment and status guards

A successful PaymentAllocation changes an APPROVED order to IN_PREPARATION
inside the existing locked payment transaction. Bank receipt/report creation
does not advance the order. Retry receipts remain idempotent; allocation on
an already CONFIRMED order preserves that status.

OperationalPlan and Compliance already accept both preparation states.
Quotation preparation, actions and assigned Coordinator access now also accept
APPROVED and IN_PREPARATION. Accepted quotation protection remains in force.
Plan confirmation advances either preparation state to CONFIRMED.
Financial and operational readiness still require their existing evidence.

## Catalogue access

Active MANAGER and COORDINATOR accounts may GET lists and details under
`/api/manager/resources/**`, including `/suppliers`, `/vehicles`, `/stalls`
and `/fit-policies`. POST/PUT catalogue writes remain MANAGER-only.
The HTTP filter and method authorization both enforce these rules.

## Optional AIR leg estimate

`PlanLegInput` accepts optional `estimatedAirfare` in USD, with up to two
fraction digits. It must be positive and belong to an AIR leg. Omitting it
keeps existing request payloads valid. Both regular drafts and graph drafts
use the same input: `legs[].estimatedAirfare` or
`draft.legs[].estimatedAirfare` respectively.

Example AIR leg, inside either draft's `legs` array:

```json
{
  "sequenceNo": 1,
  "transportMode": "AIR",
  "startPoint": "Noi Bai",
  "endPoint": "London Heathrow",
  "distanceKm": 9200,
  "plannedDeparture": "2027-02-01T08:00:00Z",
  "plannedArrival": "2027-02-01T20:00:00Z",
  "estimatedAirfare": 1500.00
}
```

Saving a draft records its acting Manager/assigned Coordinator as the distance
confirmer, with a server timestamp. If no distance source label is supplied,
the source is explicitly labelled as a staff plan estimate. Sourced draft
distances are usable for pricing; they do not confirm resources or departure.

Positive AIR estimates are summed into a selected AIRFARE SupplierOffer, with
reference `PLAN-AIRFARE:<PlanID>`, quantity 1, unit SHIPMENT and retail price
equal to that sum. **The actual schema has no QuotedAmount column**:
`RetailUnitPrice * Quantity` holds the quoted estimate. Required internal
`UnitPrice` is 0 because an estimate does not establish a supplier purchase
cost. No carrier evidence file, flight reservation or acceptance is invented.

The estimate is valid until the plan's first departure. A new current plan
with an estimate expires earlier generated estimates for that revision.
Automatic reads require the exact current plan, revision and recorded creator;
an old plan, different revision, missing/expired or ambiguous offer is unusable.
The existing parent lock and operation receipt prevent duplicate retry writes.

F05 disclosure reads the current plan estimate. F06 quotation preparation and
recalculation load it automatically when no AIRFARE source is specified,
including when the assessments list contains no AIRFARE entry. Explicit retail
sources still take precedence. Existing commercial snapshots stay frozen;
prepare a new quotation version to capture changed estimates.
Quote validity cannot exceed source validity. Other evidence blockers remain
enforced, including fit, veterinary, quarantine, tariffs and operational gates.

## Verification environment

No FE changes or production EquiTransit DDL are part of BE-01.
Native tests use `EquiTransit_FigmaMigrationTest_BE01_20261023`, a fresh test
catalog built from the baseline and migrations 001-019. Tests explicitly
allowlist this exact catalog before writing fixtures. Migration 018 used a
local test-only copy of its catalog guard; tracked migration files are unchanged.

The previously available test catalog contained published tariff versions that
collided with Payment/Quotation setup fixtures. It was not cleared or rebuilt.
The clean test catalog avoids altering that existing data.

Validation commands (Java 21, native SQL Server JDBC library configured):

```powershell
.\mvnw.cmd -B test-compile checkstyle:check
.\mvnw.cmd -B '-Dtest=*Payment*,*Quot*,*OperationalPlan*,Resource*Test,ServicePricingPolicyTest,JourneyGraphServiceTest,ApiDtoContractTest' test checkstyle:check
```

Enable the existing `EQ_PAYMENT_TEST_ENABLED`, `EQ_QUOTE_TEST_ENABLED`,
`EQ_PLAN_TEST_ENABLED` and `EQ_RESOURCE_TEST_ENABLED` opt-ins and point the
corresponding `*_TEST_DB_URL` variables at the allowlisted test catalog.
Native tests validate schema instead of generating it.

Final result (2026-10-23): both commands BUILD SUCCESS; 138 tests passed,
0 failures, 0 errors, 0 skipped, and 0 Checkstyle violations. This includes
12 Payment, 33 Quotation and 6 OperationalPlan native integration tests,
plus catalogue authorization, pricing policy, graph and DTO contract tests.
